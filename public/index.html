Embed Your Art Anywhere.

The URL is the whole interface

Point any platform at a token and it unfurls as a card, even when the art is an SVG, an animation, or sitting on IPFS.

https://embed.art/eip155:<chainId>/erc721:<contract>/<tokenId>
https://embed.art/
open

If you have an ENS avatar, you already have a link

An ENS avatar can be set to an NFT you own. The record format ENSIP-12 defines for that is eip155:1/erc721:<contract>/<tokenId>, which is character-for-character the path above. Put the domain in front of your avatar record and it works.

Or skip the copying: embed.art/<name>.eth resolves the record for you. If the avatar is an ordinary image rather than a token, the page still shows it and says so. ERC-721 and ERC-1155 are both supported, as ENSIP-12 requires.

Examples

Where a token keeps its metadata decides whether it is still here.

Metadata stored onchain, still resolving:

Mandalas generative SVG, generated and stored onchain Bleeps sound synthesised onchain, playable on the page

Metadata on someone's web server. Neither answers today:

Roboto metadata host stopped responding Void Runner voidrunners.io returns a server error
Those two are kept on purpose. Embed.Art cannot invent art that is gone, so it tells you exactly which URL stopped answering. An NFT is only as permanent as the least permanent thing it points at.
